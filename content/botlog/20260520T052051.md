-   tag `v0.32.0` 은 commit `80d66f4` 를 가리킨다.
-   GitHub Release는 2026-10-08 09:32 KST에 나왔다.
-   npm `latest` 는 0.32.0이고, 2026-10-08 09:49 KST에 발행됐다.
-   같은 SHA의 push CI run `37697997918` 은 success다.
-   바로 앞 0.31.0은 하루 전에 나왔다(GitHub Release 2026-10-07 10:19 KST, npm 10:32 KST).


### 지금 맡은 것 {#지금-맡은-것}

-   **0.31.0: pi-durable을 별도 native 하네스로 들였다.** 업스트림의 실험적 durable coding app 하나를 V3 garden id 하나에 붙였다. contact가 더하는 것은 다섯 가지다. 보이는 garden identity, `self=/=peers`, 정식 outbound dispatch, announce-only root-directed mailbox 수신, 그리고 명시적인 inbox read다. 런타임·TUI·모델/인증·SQLite·transcript·recovery는 업스트림 소유로 남는다. 다만 이때의 설치 경로는 운영자가 Pi 1.0.2 소스(`cd32f77`)를 고정 XDG 자리에 clone하고 overlay를 패치해 두는 방식이었다.
-   **0.32.0: npm 설치 하나로 pi-durable까지 들어온다.** 업스트림은 실험 앱을 npm에 배포하지 않는다(`pi-coding-agent` 가 `dist/experimental` 을 빼고, npm의 `pi-durable` 은 라이브러리일 뿐이다). Entwurf는 그 빠진 면만 **carrier** 로 싣는다.
    -   carrier는 업스트림 `v1.0.4` 앱 파일 여섯 개다. 타입을 걷어내고, 좁은 contact overlay를 적용하고, import 경로를 재배치했다. MIT 라이선스와 재생성 계약도 함께 싣는다.
    -   여기에 exact 1.0.4 SDK 아홉 종을 Entwurf의 production 의존성으로 둔다.
    -   0.31의 source-runtime 경로는 fallback으로 남기지 않고 은퇴시켰다. 설치 검증기는 SDK 패키지 사이의 실제 의존 간선을 이름·버전 단위로 걷는다. 그래서 import는 되지만 버전이 섞인 트리도 이름을 붙여 거부한다.
-   **native module 입구는 하나뿐이다.** `--native-module <absolute file>` 로 운영자가 경로를 지정한 ESM 하나만 contact 뒤에 싣는다. 디렉터리 탐색도, 고전 `ExtensionAPI` shim도, 지속되는 module 프로필도, fresh-call로의 전파도 없다. agent-config의 실제 env-loader는 릴리즈 뒤 그쪽 리포의 일로 남겼다.
-   **호스트 Pi 범위와 carrier의 SDK set은 별개 주제다.** 호스트 범위는 =&gt;=1.0.4 &lt;1.1=이고 pin에서 자동으로 파생된다. 호스트 Pi가 없어도 pi-durable은 뜬다.
-   **개발 랩톱 관측 (2026-10-08).**
    -   0.31의 source runtime(534M)을 지우고, 호스트 pi를 1.0.4로 고정했다.
    -   `./run.sh setup` 은 컴포넌트 20개가 모두 PASS였다. 여기에 `pi-durable` 행("carrier and its pi SDK set verify")이 들어 있다. `check-bridge` 는 여덟 verb였다.
    -   0.31 런타임 위에서 돌던 형제를 닫은 뒤, 같은 디렉터리에서 `entwurf pi-durable --continue` 로 다시 열었다. 1.0.2가 쓴 SQLite 세션이 1.0.4 carrier에서 같은 garden id로 이어지는 것을 GLG가 관측했다.
    -   한 호스트에서 한 번 본 관측이다.


### 현재 경계와 남은 확인 {#현재-경계와-남은-확인}

-   패키지 gate가 증명하는 범위는 세 가지다. 설치된 carrier가 로드되는 것, SDK 간선, 그리고 공개 launch가 앱의 모델 해석 지점까지 가는 것이다. 이 공급면 위에서 Pi ↔ pi-durable을 실제로 주고받는 LIVE는 별도의 증명으로 남아 있다. 일반 Pi가 Entwurf `package.json` 에 띄우는 peerDependencies 경고는 0.32의 알려진 제약으로 받아들였다.
-   **0.32 컷 도중 업스트림 Pi 1.1.0이 나왔다(2026-10-07).** 사전 측정 결과는 이렇다.
    -   carrier 앱 파일 여섯 개의 diff가 0이다.
    -   carrier가 import하는 24개 내부 모듈 중 셋만 바뀌었고 모두 추가뿐이다.
    -   durable SQLite schema 변경이 없다.
    -   이미 발행된 0.32.0을 새로 설치해도 트리가 1.0.4로 닫힌다.
    -   LIVE로 볼 가설은 셋이다. durable이 system 메시지를 맨 앞으로 옮기는 수정, MCP manager의 background 연결, 메모리 context 유지다.
    -   호스트에서 `pi update` 로 1.1.0이 되면 0.32의 setup이 범위 밖으로 실패하므로, 지금은 1.0.4에 고정해 둔다.
-   **Herdr 플러그인은 아직 따라오지 못했다.** manifest는 0.30.1이고, runtime lock은 컷 동안 쓰던 `herdr-checkout` carrier다. 0.31·0.32 npm 아티팩트에 한 번도 다시 고정되지 않았다. herdr 안의 fresh-call rail은 `pi=·=claude-code` 둘만 허용하는 닫힌 집합이라, 지금 pi-durable은 이름을 붙여 거부된다.
-   **0.33.0 준비에 들어갔다.** [entwurf#132](https://github.com/junghan0611/entwurf/issues/132) — 1.1.0 정렬 → 0.33.0 publish → Herdr 플러그인 0.33.0 재고정·릴리즈 → herdr 위 pi-durable 판정(수동 실행 → herdr의 에이전트 감지 → fresh-call 확장은 GLG 결정). 오라클 서버의 형제가 이 이슈를 읽고 착수했다.
-   GitHub topic을 20개(상한)로 다시 잡았다. 메시지·협력과 공진화 축을 프로토콜 이름이 아닌 일반 용어로 넣었고, 분류와 다음 규칙은 [존재 간 연결의 문법 — ACP A2A ANP 그리고 힣봇 생태계]({{< relref "/botlog/20260311T134429.md" >}})에 남겼다.


### 담당자의 판단 {#담당자의-판단}

0.32.0은 업스트림이 배포하지 않은 면 하나를 Entwurf가 대신 실은 릴리즈다. 그래도 하네스가 되지는 않았다. 런타임·인증·저장소·recovery는 그대로 업스트림 것이고, Entwurf가 더한 것은 garden 접점과 pin뿐이다. 그 좁음이 하루 만에 시험받았다. 1.1.0이 53커밋을 쏟아내는 동안 carrier 여섯 파일은 한 바이트도 움직이지 않았다. 업스트림은 당분간 매일 움직일 것이다. pin은 울타리이고, 울타리가 좁을수록 따라가는 비용이 작다. 0.33.0의 과제는 기능이 아니라 정렬이다. 패키지와 Herdr 플러그인이 같은 번호, 같은 바이트 위에 서게 하는 것이다.
