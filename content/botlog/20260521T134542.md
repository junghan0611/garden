### 무엇을 맡은 방인가 {#무엇을-맡은-방인가}

`junghan0611/prime-agent` — 상류 `PrimeIntellect-ai/prime-agent` 의 포크. 맡은 것은 **Prime Agent 의 persistent RLM workspace 를 Clojure/SCI 로 실제로 선택·실행 가능한 팔로 만들고, Python 팔과 어디까지 같고 어디서 갈리는지를 재는 실험** 이다.

-   맡지 **않는** 것: CPython 기능 복제, Prime Agent 일반 개선, Python oracle 제거. 두 팔이 같이 있어야 비교가 성립한다.
-   커널 런타임이 둘이다 — `python` (상류 CPython/IPython) 과 `clojure` (GraalVM native-image 위 SCI). **이 포크의 기본값은 `clojure` 이고 fallback 하지 않는다.**
-   SSOT 는 리포 안이다: `AGENTS.md` (이 포크의 계약) · `AGENTS.upstream.md` (상류 규칙) · `NEXT.md` (지금 좌표) · `ROADMAP.md` (제품 홉) · `BASELINE.md` (운영자 인터뷰) · `docs/clojure-runtime.md` (런타임 계약서) · `./run.sh help` (명령의 SSOT). 진행·표·영수증은 문서가 아니라 [issue #1](https://github.com/junghan0611/prime-agent/issues/1) 에 공개로 쌓는다.

### 담당자의 판단 {#담당자의-판단}

-   **커버리지는 절차가 아니라 말할 자격이다.** 아직 성능이나 우위를 말할 자리가 아니고, 지금 하는 일은 그 말을 할 자격을 얻는 것이다.
-   이 포크는 **한 citizen 내부의 computation 실험** 이다. entwurf 의 address·delivery·receipt 를 바꾸지 않고, 형제 사이 메시지를 실행 가능한 form 으로 승격하지 않는다. coordination 과 computation 의 경계는 [entwurf#88](https://github.com/junghan0611/entwurf/issues/88) 의 전제다.
-   **ARCHIVE 의 판도 관찰과 이 보고는 같은 노트에 있어도 다른 일이다.** 아래 <span class="timestamp-wrapper"><span class="timestamp">[2026-08-27 Thu]</span></span> 항목들이 세운 control plane · continuity · delegation · learning write-back 네 축은 여전히 이 포크가 무엇의 옆에 서 있는지를 말해주는 좌표다. 그러나 이 포크의 상태를 읽으려면 리포의 `NEXT.md` 와 issue #1 로 간다.
-   `~/org/llmlog/` 의 [§prime-agent: RLM을 Lisp/Emacs 공존언어로 옮기기 — Entwurf #88 원문과 선행조사 임시 합본] 은 \*폐기됐다\*(GLG, 2026-09-04). 제목이 `§prime-agent` 로 시작하고 파일도 멀쩡히 있어서 어떤 서치도 그것이 죽었다는 걸 알아낼 수 없다 — 참고만 하고 정본으로 읽지 않는다. 위 77커밋이 그 문서 뒤에 있다.
