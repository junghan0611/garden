## <span class="timestamp-wrapper"><span class="timestamp">[2026-08-02 Sun]</span></span> 담당자의 현재 보고 — 캡처 금고와 메타 서지의 얇은 손 {#담당자의-현재-보고-캡처-금고와-메타-서지의-얇은-손}

zotero-config는 Zotero GUI 플러그인 왕국이 아니다. Cloud는 **캡처 금고** 이고, 로컬 `*.bib` 가 **메타 서지 SSOT** 이다. 공개 리포의 정체성은 "이 책 목록을 베끼라"가 아니라 **서지를 가꾸는 과정** 을 드러내는 일이다.

```text
URL / Connector / 폰
        ↓  save (Translation Server)  — 날것 항목
에이전트 스타일 · KDC 감각 키 · 유일성
        ↓  pin --sync  — whitelist PATCH + 컬렉션 + bib sync
Zotero 적소 (Book/N00 또는 Category/Video|@Web|…)
~/org/resources/*.bib
        ↓  bibcli show / citar / #+reference:
org 글에서 바로 인용
```


### 지금 맡은 것 {#지금-맡은-것}

-   Cloud → 로컬 증분 `bib sync` / `full` (렌더는 **네트워크 없음**. 기존 citationKey 존중, 없을 때만 로컬 폴백)
-   URL 원샷: `save --json` → 에이전트 판단 → `pin --sync` (같은 세션에 키 확정, 시점 분리 금지)
-   컬렉션 자동 분류: 책 = citationKey 앞자리 → Book+N00; 비책 = itemType → Category 리프 (Unfiled 탈출)
-   `bibcli` 검색·show·(선택) lookup — SSOT 읽기 손
-   공개 sanitize 후 `output/` → `~/org/resources/`
-   Snapshot HTML 등 저장공간 쓰레기는 명시 작업으로만 정리 (부모 서지 보존)


### 맡지 않는 것 {#맡지-않는-것}

-   YouTube 별표·브라우저 북마크 대량 스크랩으로 경계 넓히기
-   BBT/GUI citation-key 플러그인 재도입, MCP로 Zotero 붙이기
-   sync 본선에 data4library/KDC API 의존 (lookup·enrich는 선택·위험 구역)
-   `dateAdded` / `dateModified` 를 위험에 두는 일괄 enrich·재생성
-   `*.bib` 손편집을 정본으로 삼기
-   책 키 대량 자동 생성·루틴 writeback
-   org 에이전트가 "서지 없어요"로 멈추는 문화 (URL 있으면 지금 pin까지)


### 현재 경계와 남은 확인 {#현재-경계와-남은-확인}

-   책 KDC는 **완벽 분류** 가 아니라 분류 축 + SSOT 유일성. 사람 손 경로(Connector+GUI)와 에이전트 레일이 공존한다
-   `enrich` / 일괄 `writeback` 은 레거시·위험 — 단건은 `pin`
-   Category 매핑은 장서 지배 패턴 기준; 예외는 `fileUnder` / `collections`
-   Translation Server (`localhost:1969`) 가용성이 원샷 캡처의 전제
-   담당자 문서 갱신 = 이 방 히스토리+현재 보고. 새 botlog/llmlog를 기본으로 만들지 않는다. 세션 핸드오프는 리포 `NEXT.md`


### 담당자의 판단 {#담당자의-판단}

과정의 유연함은 코드 본선이 아니라 **스킬과 판단** 에 둔다. 코드는 금고를 읽고, 허용된 필드만 쓰며, 타임스탬프를 지키면 충분하다. org 쪽 얼굴은 bibcli 스킬 한 장으로 "URL만 넘기면 글에 쓴다"를 닫는다. 이 집이 추천하는 것은 책이 아니라, 그렇게 서지를 가꾸는 손이다.


## <span class="timestamp-wrapper"><span class="timestamp">[2026-08-22 Sat]</span></span> 담당자의 현재 보고 — 기기 대칭의 결정론 서지면 {#담당자의-현재-보고-기기-대칭의-결정론-서지면}

이제 zotero-config는 개인 output 폴더나 Git 운반을 맡지 않는다. Zotero Cloud는 여러 기기에서 URL을 담는 금고이고, 각 기기의 .sync/는 공유하지 않는 증분 cache다. 완성된 BibTeX만 ~/sync/org/resources/bib/\*.bib에 직접 렌더되어 Syncthing으로 움직인다.

같은 Cloud 항목 집합은 cache 배열 순서·실행 시각·기기와 무관하게 같은 바이트의 BibTeX가 된다. 생성 시각 헤더는 없애고, 의미 있는 시간은 Zotero의 dateadded/datemodified로 남겼다. local full/sync/writeback은 .sync 단일 writer lock으로 보호하며, cache와 cursor는 cache·삭제 반영 뒤에만 cursor가 전진한다.

agent-config의 bibcli 스킬은 이 bib/ 면을 읽고, 어느 기기의 org 담당자든 자기 기기에서 save → 스타일·키 판단 → pin --sync로 한 세션에 인용 키를 닫는다. Git pull/push와 repo output은 일상 경로 밖이다.

현재 확인: Oracle full sync가 Cloud 6,225건을 받아 6,222개의 citeable entry를 새 bib/에 생성했고, 다음 no-op sync에서 7개 파일의 SHA-256과 mtime이 모두 유지됐다.

남은 일은 코드 커밋 판단과 별도의 Doom Emacs citar 경로 전환이며, output의 Git 정리는 코드 commit 때만 함께 판단한다.


## <span class="timestamp-wrapper"><span class="timestamp">[2026-09-04 Fri]</span></span> 담당자의 현재 보고 — id 로 정박한 담당자 문서와 bibcli 경계 {#담당자의-현재-보고-id-로-정박한-담당자-문서와-bibcli-경계}

담당자 문서를 가리키는 손잡이를 리포 안에 정박했다. `~/repos/gh/zotero-config/AGENTS.md` 의 `### Steward note` 블록이 `20260304T105300` 을 직접 든다. 제목이 아니라 id 다.

이 방이 `§zotero-config: ◊bibcli 캡처 금고와 메타 서지의 얇은 손` 으로 개명되면서 제목·슬러그·filetags·파일명이 전부 움직이는 동안 `#+identifier` 만 자리를 지켰고, 그 사이 `AGENTS.md` 는 옛 제목을 들고 있었다 (커밋 `a9b996a` 의 `AGENTS.md:14`). 제목이나 `§` 검색으로 "이 리포의 담당자 문서가 어느 방인가"를 매번 다시 유도하는 절차는 그래서 금지다. 판정은 한 번 내리고 id 로 기억한다.

읽는 자리도 같이 박았다. 근거는 `~/org/botlog/` 의 org 원본이며, `notes/content/` 의 내보내진 md 는 한 주기 늦으므로 판정 근거가 아니다.

`:hugo_lastmod:` 의 뜻도 여기서 고정한다. 퍼블리시 관심사가 아니라 **이 문서를 정말 고쳤다** 를 손으로 찍는 도장이다. 히스토리 한 줄은 로그이지 수정이 아니므로 기준선을 올리지 않는다.


### bibcli 경계 — 제목의 ◊bibcli 는 오기가 아니다 {#bibcli-경계-제목의-bibcli-는-오기가-아니다}

이 방 하나가 두 얼굴을 든다. 갈림은 리포가 아니라 **면** 이다.

-   `bibcli/` — Go 소스·파서·=lookup= 은 **이 리포 안에** 산다. 별도 리포는 없다 (`~/repos/gh/bibcli` 부재 실측, 2026-09-04). 고치는 손은 이 집 담당자다.
-   `~/.claude/skills/bibcli/SKILL.md` — org 에이전트에게 노출되는 사용 설명면은 `agent-config` 소유다. 이 집이 직접 고치지 않고 발견을 넘긴다.
-   그러므로 제목의 `◊bibcli` 는 다른 집으로 넘기는 표시가 아니라, 캡처·렌더의 집과 그 SSOT 를 읽는 손이 한 얼굴이라는 표시다. 이 방을 bibcli 쪽 주제 노트로 오인해 zotero-config 의 담당자 문서를 따로 찾으면 안 된다 — 그런 방은 없고, 없는 게 맞다.


### 관련노트의 옛 경로 한 줄 {#관련노트의-옛-경로-한-줄}

위 `관련노트` 에 남은 `~/org/resources/*.bib` 는 2026-08-22 이전 좌표다. 지금의 서지면은 `$ZOTERO_BIB_DIR` (기본 `~/sync/org/resources/bib/`) 하나이고 렌더러가 거기에 직접 쓴다. `BIBCLI_DIR` 은 폐기됐다. 옛 줄은 흔적으로 남기고 좌표는 여기서 정정한다.
