## <span class="timestamp-wrapper"><span class="timestamp">[2026-08-02 Sun]</span></span> 담당자의 현재 보고 — 캡처 금고와 메타 서지의 얇은 손 {#담당자의-현재-보고-캡처-금고와-메타-서지의-얇은-손}

zotero-config는 Zotero GUI 플러그인 왕국이 아니다. Cloud는 **캡처 금고** 이고, 로컬 `*.bib` 가 **메타 서지 SSOT** 이다. 공개 리포의 정체성은 "이 책 목록을 베끼라"가 아니라 **서지를 가꾸는 과정** 을 드러내는 일이다.

```text
URL / Connector / 폰
        ↓  save (Translation Server)  — 날것 항목
에이전트 스타일 · KDC 감각 키 · 유일성
        ↓  pin --sync  — whitelist PATCH + 컬렉션 + bib sync
Zotero 적소 (Book/N00 또는 Category/Video|@Web|…)
~/org/resources/*.bib
        ↓  bibcli show / citar / #+reference:
org 글에서 바로 인용
```


### 지금 맡은 것 {#지금-맡은-것}

-   Cloud → 로컬 증분 `bib sync` / `full` (렌더는 **네트워크 없음**. 기존 citationKey 존중, 없을 때만 로컬 폴백)
-   URL 원샷: `save --json` → 에이전트 판단 → `pin --sync` (같은 세션에 키 확정, 시점 분리 금지)
-   컬렉션 자동 분류: 책 = citationKey 앞자리 → Book+N00; 비책 = itemType → Category 리프 (Unfiled 탈출)
-   `bibcli` 검색·show·(선택) lookup — SSOT 읽기 손
-   공개 sanitize 후 `output/` → `~/org/resources/`
-   Snapshot HTML 등 저장공간 쓰레기는 명시 작업으로만 정리 (부모 서지 보존)


### 맡지 않는 것 {#맡지-않는-것}

-   YouTube 별표·브라우저 북마크 대량 스크랩으로 경계 넓히기
-   BBT/GUI citation-key 플러그인 재도입, MCP로 Zotero 붙이기
-   sync 본선에 data4library/KDC API 의존 (lookup·enrich는 선택·위험 구역)
-   `dateAdded` / `dateModified` 를 위험에 두는 일괄 enrich·재생성
-   `*.bib` 손편집을 정본으로 삼기
-   책 키 대량 자동 생성·루틴 writeback
-   org 에이전트가 "서지 없어요"로 멈추는 문화 (URL 있으면 지금 pin까지)


### 현재 경계와 남은 확인 {#현재-경계와-남은-확인}

-   책 KDC는 **완벽 분류** 가 아니라 분류 축 + SSOT 유일성. 사람 손 경로(Connector+GUI)와 에이전트 레일이 공존한다
-   `enrich` / 일괄 `writeback` 은 레거시·위험 — 단건은 `pin`
-   Category 매핑은 장서 지배 패턴 기준; 예외는 `fileUnder` / `collections`
-   Translation Server (`localhost:1969`) 가용성이 원샷 캡처의 전제
-   담당자 문서 갱신 = 이 방 히스토리+현재 보고. 새 botlog/llmlog를 기본으로 만들지 않는다. 세션 핸드오프는 리포 `NEXT.md`


### 담당자의 판단 {#담당자의-판단}

과정의 유연함은 코드 본선이 아니라 **스킬과 판단** 에 둔다. 코드는 금고를 읽고, 허용된 필드만 쓰며, 타임스탬프를 지키면 충분하다. org 쪽 얼굴은 bibcli 스킬 한 장으로 "URL만 넘기면 글에 쓴다"를 닫는다. 이 집이 추천하는 것은 책이 아니라, 그렇게 서지를 가꾸는 손이다.

## 옛 설계 흡수 — No-GUI / AI-Queryable (from 20250409T144103) {#옛-설계-흡수-no-gui-ai-queryable--from-20250409t144103}

2025–2026 초에 notes에 있던 설계 메모를 여기로 옮긴다. **현재 운영 계약은 위 «담당자의 현재 보고»가 SSOT** 이며, 아래는 출발 기록이다.


### 당시 확인한 사실 {#당시-확인한-사실}

-   Cloud API에 citationKey가 남을 수 있음; `format=bibtex` 가 키를 존중하는 경로가 있었음
-   증분 `since` 동기화 가능
-   기본 BibTeX export만으로는 `dateadded` / `datemodified` / `callnumber` 가 빠질 수 있어 JSON 경로가 필요했음
-   DATA4LIBRARY(ISBN→KDC)는 **선택 보조**; 본선 자동 의존 금지로 정리됨


### 당시 파이프라인 스케치 {#당시-파이프라인-스케치}

```text
Cloud JSON → citationKey 존중/생성 → citar 호환 BibTeX
  → Book.bib / 기타 분리 → (위험) key writeback → .sync 상태
```

이후 구멍(특히 타임스탬프·일괄 writeback)을 보고 **pin whitelist + 네트워크 없는 sync 렌더 + 스킬 판단** 으로 얇아졌다.


### 설치 아카이브 {#설치-아카이브}

우분투 deb 패키지·베타 버전 이슈 등은 출발 삽질. 현재 환경은 리포/ Nix 경로를 본다.


## 메타데이터 허브 비전 (from 20240822T155719) {#메타데이터-허브-비전--from-20240822t155719}

조테로를 책만이 아니라 영화·음악·블로그·링크의 **공통 캡처 인터페이스** 로 쓰려는 초기 감각. 해석은 나의 몫, 저장은 확실한 공통 포맷. 현재 Video/Online/Software 분리 bib와 Category 자동 분류가 그 연장이다. IMDb 등 개별 DB 연동 실험은 여기 비전만 남기고 확장하지 않는다.


## Translation Server 출발 메모 (from 20250409T142618) {#translation-server-출발-메모--from-20250409t142618}

GUI/브라우저 없이 URL을 담고 싶다는 요청에서 translation-server(`:1969`) 경로가 열렸다. 현재 원샷은 `save --json` → 스타일/ 키 → `pin --sync`. Emacs 쪽 «조테로 필요 없다, bib+citar면 된다» 감각과 file= 첨부 실무는 [Emacs 서지 허브]({{< relref "/notes/20240416T072524.md" >}})에 둔다.
