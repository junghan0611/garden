## 해설 — 왜 다시 Forge인가 {#해설-왜-다시-forge인가}

1탄 수선 당시 표에는 forge 풀세트가 «기본 제외 경향»으로 남아 있었다. consult-gh 재도입이 급한 날의 경계였다. 그로부터 며칠, 목적이 선명해졌다.

-   **가장 큰 목적**: 개인 리포 이슈를 쭉 보고 상황 판단.
-   이슈의 실체: 사람↔사람이 아니라 **사람↔에이전트** 소통 채널.
-   고통: 브라우저 탭 순회는 느리고 답답하다. GitHub 자체가 느릴 때 `gh` 매번 호출도 왕복이다.
-   가설이 곧 설계: Forge가 DB를 쥐니, pull 이후 열람은 로컬이다.

실측(2026-08-23, thinkpad·user 소켓):

-   `(magit +forge)` 이미 on. 패키지·DB 파일 존재.
-   `authinfo.gpg`: `junghan0611^forge`, `jhkim2tbdhny^forge` 둘 다 `/user` 200.
-   그러나 DB는 비어 있었다(repo 1 stub / issue 0). 토큰만 살리고 pull·seeding이 없으면 인박스는 없다.
-   개인 open 이슈 스냅샷: 약 65개 / ~20 repo (엔트로프·agent-config·homeagent 등이 두꺼움).

즉 «Forge를 넣느냐»가 아니라 «인박스로 \*쓰느냐\*»의 문제였다. 돌아 돌아 결국 Forge가 필요하다.


## 해설 — 표면 분담 (2탄 확정) {#해설-표면-분담--2탄-확정}

| 표면                       | 누가     | 무엇을                                                 | 네트워크              |
|--------------------------|--------|-----------------------------------------------------|-------------------|
| **Magit Forge**            | 인간 (인박스) | 추적 repo 이슈 _PR_ 댓글 열람·작성. `forge-list-global-issues` 등 | pull 때만. 이후 로컬 SQLite |
| **consult-gh**             | 인간 (검색) | «어느 repo였지?» 즉석 검색. `SPC g h i`                | 호출마다 `gh`         |
| **magit-gh**               | 인간     | **현재** Magit repo PR 보조                            | 즉석                  |
| **ghcli**                  | 에이전트 | 이슈 _PR_ 댓글 CRUD                                    | CLI 왕복              |
| **브라우저**               | 최후 수단 | 미리보기·설정·Forge가 안 닿는 모서리                   | 항상 무거움           |
| **forge-config (Forgejo)** | 에이전트 공방 | 별축 운영면. GitHub 인박스와 혼동 금지                 | 자체 호스트           |

한 줄 지도:

```text
사람 인박스 /열람/ 댓글  = Magit Forge  (local DB)
사람 즉석 검색/발견    = consult-gh
에이전트 CRUD          = ghcli
PR 보조                = magit-gh
에이전트 공방(별축)    = forge-config / Forgejo
```


## 해설 — 인박스를 살아 있게 {#해설-인박스를-살아-있게}

1.  토큰: `~/.authinfo.gpg`
    
    ```text
    machine api.github.com login USER^forge password TOKEN
    ```
2.  (선택) `forge-owned-accounts` 에 개인 계정.
3.  관심 개인 repo에서 Magit → `forge-pull` / 저장소 추가. **repo 단위 seeding** 이 초기 비용.
4.  전역 목록: `forge-list-global-issues` (및 notifications).
5.  에이전트가 방금 쓴 댓글은 pull 전까지 stale일 수 있다 — 인박스 열 때 갱신, 또는 주기 pull.

설정 세부의 SSOT는 닷파일. 이 방은 **왜 이 면이 인간에게 귀중한가** 만 고정한다.


## 오독 주의 {#오독-주의}

-   이 방의 Forge ≠ [forge-config]({{< relref "/botlog/20260527T073823.md" >}}) Forgejo 봇공방. 이름만 겹친다.
-   Magit Forge를 에이전트 기본 도구로 읽지 않는다. 에이전트는 ghcli.
-   consult-gh를 인박스로 읽지 않는다. 검색창이다.
-   «로컬 DB = 항상 최신»이 아니다. pull 리듬이 계약의 일부다.
-   2024 Q&amp;A의 `forge-browse-issues` 일변도 안내를 현재 UX 전체로 확대하지 않는다.

## 접힌 외부 매뉴얼 잔재 {#접힌-외부-매뉴얼-잔재}

구 본문의 use-package 설치 스니펫·authinfo 초보 안내·=forge-browse-issues= 일변 답변·gitconfig 전문 덤프는 어쏠로그 수선 시 본문에서 제거. 인증·모듈 on/off의 살아 있는 SSOT는 doomemacs-config와 `~/.authinfo.gpg`.
