## Claude Code &amp; OpenCode 에이전트 통합 구성 {#claude-code-and-opencode-에이전트-통합-구성}


### 개요 {#개요}

Claude Code와 OpenCode에서 사용할 전문 에이전트 시스템을 일관성 있게 구성했습니다. 총 12개의 에이전트를 개발 라이프사이클 전반을 커버하도록 설계했으며, 각 플랫폼의 양식에 맞춰 동일한 에이전트 세트를 적용했습니다.


### 에이전트 구성 철학 {#에이전트-구성-철학}


#### 명확한 역할 분담 {#명확한-역할-분담}

-   각 에이전트는 하나의 명확한 책임을 가짐
-   역할 간 중복 최소화
-   전문성 극대화


#### 모델 전략적 배치 {#모델-전략적-배치}

-   Haiku (2개): 빠른 응답이 필요한 작업 (git, tester)
-   Sonnet (10개): 표준 작업, 품질 중시


#### Temperature 최적화 {#temperature-최적화}

-   0.1: 정확성 최우선 (5개)
-   0.2: 체계적 일관성 (2개)
-   0.3: 구조적 창의성 (1개)
-   0.4: 자연스러운 문서 (1개)
-   0.6: 탐색적 조사 (1개)
-   0.7: 창의적 설계 (1개)
-   0.8: 자연스러운 표현 (1개)


### 전체 에이전트 목록 (12개) {#전체-에이전트-목록--12개}


#### 기본 개발 워크플로우 (6개) {#기본-개발-워크플로우--6개}


##### reviewer (sonnet, 0.1) {#reviewer--sonnet-0-dot-1}

-   역할: 코드 품질/보안 리뷰
-   도구: Read, Grep, Glob (읽기 전용)
-   특징: 정확한 분석, 보안 취약점 탐지
-   사용 시점: 코드 작성 후 품질 검토


##### refactor (sonnet, 0.3) {#refactor--sonnet-0-dot-3}

-   역할: 코드 리팩토링
-   도구: Read, Write, Edit, Grep, Glob, Bash
-   특징: 구조 개선, 성능 최적화
-   사용 시점: 코드베이스 개선


##### debugger (sonnet, 0.2) {#debugger--sonnet-0-dot-2}

-   역할: 버그 추적 및 디버깅
-   도구: Read, Grep, Glob, Bash
-   특징: 체계적 근본 원인 분석
-   사용 시점: 에러 조사, 버그 해결


##### architect (sonnet, 0.7) {#architect--sonnet-0-dot-7}

-   역할: 시스템 아키텍처 설계
-   도구: Read, Write, Grep, Glob + WebSearch, Context7
-   특징: 창의적 시스템 설계, 기술 의사결정
-   사용 시점: 시스템 설계, 기술 스택 선택


##### researcher (sonnet, 0.6) {#researcher--sonnet-0-dot-6}

-   역할: 기술 조사 및 라이브러리 비교
-   도구: Read, Grep + WebSearch, WebFetch, Context7
-   특징: 탐색적 조사, 베스트 프랙티스 발견
-   사용 시점: 기술 선택, 솔루션 탐색


##### tester (haiku, 0.1) {#tester--haiku-0-dot-1}

-   역할: 시스템 테스트, 로그 분석
-   도구: Read, Write, Bash, Grep, Glob
-   특징: 빠른 로그 분석, 원격 시스템 관리
-   사용 시점: 테스트 실행, 모니터링


#### 문서화 워크플로우 (2개) {#문서화-워크플로우--2개}


##### docs (sonnet, 0.4) {#docs--sonnet-0-dot-4}

-   역할: 기술 문서 작성
-   도구: Read, Write, Edit, Grep, Glob
-   특징: 명확하고 간결한 문서
-   사용 시점: README, API 문서, 가이드 작성


##### translator (sonnet, 0.8) {#translator--sonnet-0-dot-8}

-   역할: 한영 번역 및 현지화
-   도구: Read, Write, Edit
-   특징: 자연스러운 표현, 문화적 맥락 고려
-   사용 시점: 문서 번역, 블로그 현지화


#### 관리 워크플로우 (4개) {#관리-워크플로우--4개}


##### pm (sonnet, 0.2) {#pm--sonnet-0-dot-2}

-   역할: 프로젝트 관리, 메모리 관리
-   도구: Read, Write, Grep, Glob, Bash
-   특징: 능동적 메모리 스캔, 문서 정리
-   사용 시점: 프로젝트 상태 점검, 문서 통합


##### org (sonnet, 0.1) {#org--sonnet-0-dot-1}

-   역할: Org-mode PKM 관리
-   도구: Read, Write, Edit, Grep, Glob, Bash
-   특징: 구조적 파싱, Denote 표준 준수
-   사용 시점: Org-mode 파일 작업, 지식 관리


##### git (haiku, 0.1) {#git--haiku-0-dot-1}

-   역할: Git 커밋 전문
-   도구: Bash, Read, Grep + MCP git
-   특징: 전문적인 커밋 메시지, 빠른 처리
-   사용 시점: 변경사항 커밋


##### security (sonnet, 0.1) {#security--sonnet-0-dot-1}

-   역할: 보안 포렌식 분석
-   도구: Read, Write, Grep, Glob, Bash
-   특징: 취약점 분석, 로그 포렌식
-   사용 시점: 보안 감사, 사고 조사

### 플랫폼별 구성 {#플랫폼별-구성}


#### Claude Code 구성 {#claude-code-구성}


##### 위치 {#위치}

```text
~/.claude/agents/
```


##### 양식 {#양식}

```yaml
---
name: agent-name
description: 설명
tools: Tool1, Tool2, Tool3
model: haiku | sonnet | opus
temperature: 0.1-0.8
---
```


##### 특징 {#특징}

-   간단한 YAML frontmatter
-   쉼표로 구분된 도구 목록
-   Claude 모델명 직접 사용 (haiku, sonnet)


#### OpenCode 구성 {#opencode-구성}


##### 위치 {#위치}

```text
~/claude-config/opencode/agent/
```


##### 양식 {#양식}

```yaml
---
description: 설명
mode: subagent
model: anthropic/claude-[model]-4-5
temperature: 0.1-0.8
tools:
  read: true/false
  write: true/false
  edit: true/false
  grep: true/false
  glob: true/false
  bash: true/false
  list: true/false
---
```


##### 특징 {#특징}

-   mode: subagent 필수
-   명시적인 모델 경로 (anthropic/claude-\*)
-   도구별 boolean 객체 구조

### 사용 예시 {#사용-예시}


#### Claude Code {#claude-code}

```bash
@reviewer 이 코드 검토해줘
@architect 마이크로서비스 아키텍처 설계해줘
@researcher Python 비동기 프레임워크 비교해줘
@translator 이 README 영어로 번역해줘
@debugger 스택 트레이스 분석해줘
```


#### OpenCode {#opencode}

```bash
@reviewer 코드 리뷰
@git 커밋 메시지 작성
@tester 로그 분석
```


### 주요 개선 사항 {#주요-개선-사항}

-   특정 기술 중심 (임베디드, OpenWrt)
-   불명확한 네이밍 (code-reviewer, openwrt-manager)
-   Opus 모델 사용

-   간단하고 명확한 네이밍 (reviewer, tester)
-   Haiku/Sonnet 전략적 배치
-   Temperature 최적화
-   양쪽 플랫폼 일관성

### 작업 이력 {#작업-이력}


#### 2025-11-21 초기 구성 {#2025-11-21-초기-구성}

1.  Claude Code 에이전트 디렉토리 생성
2.  기본 8개 에이전트 생성
    -   reviewer, refactor, pm, org, git, docs, security, tester
3.  모델 최적화 (opus → sonnet, reviewer haiku → sonnet)
4.  tester 모델 변경 (sonnet → haiku)
5.  전체 에이전트에 temperature 설정 추가
6.  4개 에이전트 추가
    -   architect, researcher, translator, debugger
7.  OpenCode 양식으로 12개 에이전트 변환
8.  기존 OpenCode 에이전트 삭제 및 신규 생성


### 향후 고려사항 {#향후-고려사항}


#### 잠재적 추가 에이전트 {#잠재적-추가-에이전트}

-   optimizer: 성능 최적화 전문
-   deployer: 배포 및 운영 관리
-   teacher: 기술 학습 및 교육 콘텐츠


#### 개선 방향 {#개선-방향}

-   MCP 도구 통합 활용
-   에이전트 간 협업 워크플로우
-   프로젝트별 커스텀 에이전트


### 결론 {#결론}

통일된 에이전트 시스템을 통해 Claude Code와 OpenCode 양쪽에서 일관된 워크플로우를 구축했습니다. 각 에이전트는 명확한 역할을 가지며, 전체적으로 소프트웨어 개발 라이프사이클을 완전히 커버합니다.

모델과 temperature의 전략적 배치를 통해 품질과 성능의 균형을 맞췄으며, 앞으로 필요에 따라 추가 에이전트를 쉽게 확장할 수 있는 구조입니다.
