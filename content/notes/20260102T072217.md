## 한 줄 {#한-줄}

> `entwurf` 는 더 많은 오케스트레이션 기능이 아니라, 각 하네스가 자기 경계를 지키면서도 힣의 드라이버 하나로 서로를 부를 수 있게 하는 설치면의 결계다.


## 세 편의 같은 맥락 {#세-편의-같은-맥락}

세 원문은 시간상으로 0.12.0-pre → 0.12.2 release → Fable 설치면 편지 순서다. 그러나 주제는 버전 번호가 아니다.

첫 글은 이름을 바꾸는 이유를 말한다. `pi-shell-acp` 라는 이름은 pi와 ACP를 중심으로 둔다. 하지만 실제 방향은 각 모델사의 네이티브 하네스, 즉 Claude Code, Codex, agy, pi가 자기 자리에서 태어난 그대로 연결되는 쪽으로 이동했다. 그러므로 이름은 `entwurf` 여야 한다. 중심은 프로토콜이 아니라 분신도구상자다.

둘째 글은 release 표면의 짧은 문장이다. `garden-citizen dispatch substrate`, `thin bridge`, `without pretending to own transcript/auth/runtime`. 이 한 줄은 첫 글의 긴 왜?!를 영어 공개면으로 압축한다.

셋째 글은 설치면으로 내려간다. 얇은 bridge일수록 실제 보장해야 하는 것은 설치와 배선이다. 상태바의 물음표는 장식이 아니라 트립와이어다. 배선이 끊기면 바로 보이고, 그러면 설치 경계를 다시 조인다. `run.sh setup` 은 개발자 설치의 멱등 한 방이고, npm 설치는 소비자의 배선을 책임지는 공개 계약이다.


## 경계를 다루는 프로젝트 {#경계를-다루는-프로젝트}

`entwurf` 는 “많은 에이전트를 멋지게 부리는 두꺼운 오케스트레이터”가 아니다. 오히려 반대다. 각 하네스가 이미 가진 오케스트레이터 기능, 투두, 메모리, 서브에이전트, 내장 도구를 모두 켜면 서로 친구가 될 수 없다. 그래서 힣은 빼라고 말한다. 각 학교 친구들에게 하나의 드라이버만 쥐여준다.

그 드라이버는 소유하지 않는다. transcript를 가져오지 않고, auth를 탈취하지 않고, runtime을 대신하지 않는다. 대신 garden id로 부른다. 이것이 thin이다. 얇기 때문에 약한 것이 아니라, 얇아야 각자의 경계가 보존된다.

이 경계 감각 때문에 ACP도 “버린다/받는다”의 단순한 결론이 아니다. 범용 중심축으로서 ACP를 내려놓되, 기업용 하네스나 Snowflake Cortex 같은 경우를 위한 얇은 pi ACP plugin은 다시 받아준다. 정공법이면 남기고, 정공법이 아니면 버린다.


## 설치면은 철학이다 {#설치면은-철학이다}

설치면은 기술 지원 항목이 아니다. `entwurf` 의 실체가 얇은 배선이라면, 설치는 곧 존재 방식이다. 개발자는 로컬 체크아웃에서 `run.sh setup` 한 방으로 배선을 회복해야 하고, 소비자는 npm 설치 후 권고된 설정으로 Claude Code, pi, claude-agent-acp 쪽 배선이 깔려야 한다.

그래서 상태바의 물음표는 실패가 아니라 성공한 경보일 수 있다. 배선이 끊겼는데 조용히 넘어가는 것이 진짜 실패다. 물음표가 떠야 한다. “여기 경계가 풀렸다”고 말해야 한다. 그때 maintainer는 다시 결계를 조인다.

Fable 답장은 이 원칙을 실측으로 확인한다. smoke가 uninstall의 honest inverse를 실제 checkout에 실행해 `.assembled` 를 삭제했고, 그 결과 새 Claude Code 세션에서 meta-bridge plugin이 로드되지 않았다. check는 초록이었지만, 실제 개발자 배선은 잘렸다. 이 사건은 “검증이 검증 대상을 파괴하면 안 된다”는 새 gate를 요구한다.


## 0.12.3~0.13.0 — 결계는 사건 이후에도 계속 조여졌다 {#0-dot-12-dot-3-0-dot-13-dot-0-결계는-사건-이후에도-계속-조여졌다}

<span class="timestamp-wrapper"><span class="timestamp">[2026-07-30 Thu 19:58]</span></span> @pi@oracle — entwurf 리포 CHANGELOG·git log 대조

Fable의 실측 판정(위 편지의 배경)은 한 번의 사고 복구로 끝나지 않았다. 이어진 릴리즈들은 같은 결계를 매번 다른 틈에서 다시 조였다.

-   **0.12.8 — 주소 권위를 하나로 좁힌다.** meta-record가 유일한 주소 권위가 되었다(#50 hard cut). 옛 `entwurf=/=entwurf_resume=/=entwurf_send` 툴과 `pi/entwurf-targets.json`, `setup:links` 가 삭제되고, v3 이전 저장소를 든 호스트는 install·setup·시민 탄생을 명시적 세대 절단(`meta-bridge-fresh-cut`) 전까지 전부 거부한다. 점진적 이관이 아니라 절단이다.
-   **0.12.8-repair.0 — 셸 형태를 완전히 버린다.** 실제 호스트에서 Claude가 `/bin/bash -c` 래퍼를 유지해 훅의 PID 소유권이 어긋나는 사고가 났다. 이식 가능한 셸 위상을 계속 고치는 대신, 모든 meta-bridge 훅을 exec 형태로 선언해 셸 자체를 발사 경로에서 들어냈다. Claude Code 2.1.217 미만은 install이 아예 거부한다.
-   **0.12.8-repair.1 — "부팅되지만 배달되지 않는" 구멍을 막는다.** npm 배포본이 capability registry를 실제 emitted MCP 브릿지 위치에 담지 못해, 설치는 되는데 `entwurf_v2` 배달만 조용히 죽는 사고가 났다. 이제 doctor는 형태가 아니라 실제 배달을 증명한다.
-   **0.12.9 — 설정을 있는 그대로 보존한다.** `setup` 이 전체 설치 경로에서 리포의 추적된 pi 설정을 보존하도록 두 작성기를 하나의 직렬화기로 합쳤다. 있을 수 없는 PID(1)를 소유자로 인정하지 않는 정책도 이때 자리잡았다.
-   **0.13.0 — 새 학교 친구를 들이면서도 경계를 새로 긋는다.** Snowflake Cortex Code가 entwurf의 첫 non-Claude ACP 백엔드로 합류했다. 핵심은 세션 범위의 이중 HOME 오버레이다. Cortex의 설정·스킬·훅 표면은 격리된 HOME 아래서만 돌고, 주변 `CORTEX_HOME` 은 빈 문자열까지 명시적으로 거부되며, 실제로 건네는 인증은 측정된 최소치(`connections.toml`, 선택적 `config.toml`, `credential_cache` 심볼릭 링크 하나)뿐이다. "각 하네스가 자기 경계를 지키면서도 힣의 드라이버 하나로 서로를 부른다"는 이 방의 중심 문장이, 넷째 이후로 새로 들어오는 하네스에게도 같은 방식으로 적용된다는 뜻이다.

사고 하나를 고치는 것과, 그 사고가 다시 나지 않도록 결계를 구조적으로 다시 긋는 것은 다르다. 0.12.3부터 0.13.0까지의 릴리즈들은 후자를 반복했다. 매번 다른 이름의 틈이었지만, 매번 같은 질문으로 돌아왔다 — 무엇을 소유하지 않을 것인가.


## 0.13.1~0.14.0 — 검증도 제품을 삼키지 않는다 {#0-dot-13-dot-1-0-dot-14-dot-0-검증도-제품을-삼키지-않는다}

<span class="timestamp-wrapper"><span class="timestamp">[2026-08-10 Mon 10:35]</span></span> @mitsein/gpt-5.6-sol — `llmlog/20260808T173829` 의 영속 논지를 선별 이관

설치 smoke가 실제 checkout의 배선을 잘라버린 사건은 국지적 버그가 아니었다. 검증이 정직하려면 더 많은 게이트를 쌓는 것만으로는 부족하다. 검증 자체가 제품 개발의 시간과 후보, 산문, 역할을 소유하려 들지 않아야 한다. #62에서 드러난 손으로 지은 `scripts/` 51,295줄과 missing-contract는 이 문제의 기준점이었다. 텍스트를 읽는 게이트는 많았지만, escape 안 된 `[` 하나가 실제 regex 엔진에서 터지는 계약은 아무도 관측하지 않았다.

\#69·#70은 이 검증면을 네 층으로 다시 나눴다.

-   **core** — 일상 편집마다 도는 `pnpm check`. oracle reference host에서 ≤60초 예산을 지키고 다른 호스트에서는 시간을 투명하게 출력한다.
-   **deterministic full** — push CI·release-gate·=prepublishOnly= 가 `check:full` 이라는 같은 바닥에 동의한다.
-   **qualification** — mutation으로 게이트 자체의 품질을 증명하되 제품 편집마다 같은 세금을 물리지 않는다.
-   **LIVE release evidence** — 실제 백엔드를 태운 증거는 release 후보와 결박된 시점에만 효력이 있다.

이 계층은 빠른 검사를 위로 올린 성능 최적화가 아니다. 각 검사가 **무슨 의미를 증명하는가** 에 따라 비용과 호출 시점을 나눈 경계 설계다. 감산도 검증 포기가 아니었다. infra replant 84건을 direct assertion 84건으로 1:1 승계하고, 제품 경로를 죽이는 product replant는 남겼다. 검증 인프라가 자기 자신을 겨냥하던 중복을 덜어내되 무엇이 사라지고 무엇이 이어받았는지 대응표로 증명했다.
