## [2025-01-20 W03]({{< relref "/journal/20250120T000000.md" >}}) {#2025-01-20-w03--relref-journal-20250120t000000-dot-md}

@user 리눅스 쉘에서 gl 커맨드가 alias로 할당 되어 있는 것 같아. 근데 무슨 커맨드 인지 모르겠어. 찾는 방법은?

@assistant 리눅스 쉘에서 `gl` 커맨드가 어떤 명령어에 해당하는지 확인하려면以下의 방법을 사용할 수 있습니다.


#### alias 조회 {#alias-조회}

다음 명령어를 사용하여 현재 설정된 모든 alias를 확인할 수 있습니다.

```bash
alias
```

이 명령어를 실행하면 모든 등록된 alias 목록이 출력됩니다. 여기서 =gl=이 무엇을 의미하는지 확인할 수 있습니다.


#### 특정 alias 조회 {#특정-alias-조회}

특정 alias인 =gl=만 확인하려면 다음 명령어를 사용합니다.

```bash
alias gl
```

이 명령어를 실행하면 `gl` alias에 해당하는 명령어가 출력됩니다.


#### 예시 {#예시}

예를 들어, =gl=이 Git 관련 명령어일 경우 다음과 같은 출력이 될 수 있습니다.

```bash
alias gl='git log --pretty=format:"%Cgreen%h%Creset %s %C(bold blue)%cr %C(yellow)%d %an %Creset " --abbrev-commit;'
```

이렇게 하면 `gl` alias가 어떤 명령어를 실행하는지 정확히 알 수 있습니다[2][3][5].

@user 해당 alias를 지우고 싶은데 어디에 설정되어 있는지 모르겠어

@assistant 리눅스에서 특정 alias가 어디에 설정되어 있는지 확인하고 삭제하려면以下의 단계를 따라야 합니다.


#### 1. alias 조회 {#1-dot-alias-조회}

먼저 현재 설정된 alias를 조회합니다.

```bash
alias
```

이 명령어를 실행하면 현재 설정된 모든 alias가 출력됩니다. 여기서 `gl` alias가 어떤 명령어에 해당하는지 확인할 수 있습니다.


#### 2. 설정 파일 확인 {#2-dot-설정-파일-확인}

alias는 일반적으로 다음 파일들에 설정되어 있습니다:

-   **시스템 전역 설정 파일**:
    -   `/etc/profile`
    -   `/etc/bashrc`
    -   `/etc/profile.d/*.sh`[2][4]

-   **사용자별 설정 파일**:
    -   `~/.bash_profile`
    -   `~/.bash_login`
    -   `~/.profile`
    -   `~/.bashrc`[2][4]


#### 3. 파일 검색 {#3-dot-파일-검색}

위의 파일들을 열어 `gl` alias가 설정되어 있는지 확인합니다.

```bash
grep 'alias gl' /etc/profile /etc/bashrc ~/.bash_profile ~/.bash_login ~/.profile ~/.bashrc
```

이 명령어는 해당 파일들에서 `alias gl` 문자열을 검색하여 설정된 위치를 표시해줍니다.


#### 4. alias 삭제 {#4-dot-alias-삭제}

설정된 파일을 열어 해당 라인을 삭제하거나 주석 처리합니다.

```bash
# 예시: ~/.bashrc 파일을 열어 수정
vi ~/.bashrc

# 해당 라인 삭제 또는 주석 처리
# alias gl='git log --pretty=format:"%Cgreen%h%Creset %s %C(bold blue)%cr %C(yellow)%d %an %Creset " --abbrev-commit;'

# 저장 후 종료
```


#### 5. 변경사항 적용 {#5-dot-변경사항-적용}

설정 파일을 수정한 후, 변경사항을 적용하기 위해 쉘을 재시작하거나 `source` 명령을 사용합니다.

```bash
source ~/.bashrc
```


#### 6. alias 삭제 확인 {#6-dot-alias-삭제-확인}

마지막으로, `unalias` 명령을 사용하여 현재 세션에서 alias를 삭제할 수 있습니다.

```bash
unalias gl
```

이렇게 하면 현재 세션에서 `gl` alias가 삭제됩니다. 그러나 다음 세션에서 다시 로드되지 않도록 위에서 설명한 설정 파일에서 해당 라인을 삭제해야 합니다[3][5].

@user gitless라는 패키지를 찾아봐줘

@assistant =gitless=는 Git 위에 구축된 간단한 버전 컨트롤 시스템입니다. 여기서 중요한 점들을 요약해 드리겠습니다.


### 주요 특징 {#주요-특징}

-   **간단한 커밋 워크플로우**: 트랙 또는 언트랙 파일을 통해 커밋할 변경 사항을 제어할 수 있습니다. 트랙된 파일의 변경 사항은 기본적으로 커밋되지만, 플래그를 사용하여 커밋할 파일 집합을 쉽게 맞출 수 있습니다[1][2][3].
-   **독립적인 브랜치**: 브랜치에는 작업 중인 변경 사항이 포함되어 있으므로 브랜치를 переключ할 때 未커밋된 변경 사항에 대한 충돌을 걱정할 필요가 없습니다.
-   **친절한 명령줄 인터페이스**: `gitless` 명령은 좋은 피드백을 제공하고 다음 단계를 결정하는 데 도움을 줍니다.
-   **Git과 호환**: =gitless=는 Git 위에 구현되었기 때문에 언제든지 Git으로 돌아갈 수 있으며, GitHub이나 기타 Git 호스팅 서비스와 함께 사용할 수 있습니다.


### 설치 방법 {#설치-방법}

-   **바이너리 릴리즈**: macOS와 Linux용 바이너리 릴리즈를 다운로드하여 설치할 수 있습니다.
    ```bash
      $ cp path-to-downloaded-gl-binary /usr/local/bin/gl
    ```
-   **소스 코드로부터 설치**: Python 3.7+와 pygit2를 설치한 후 소스 코드를 다운로드하여 설치할 수 있습니다.
    ```bash
      $ ./setup.py install
    ```
-   **Python Package Index를 통해 설치**:
    ```bash
      $ pip install gitless
    ```
-   **Homebrew를 통해 설치 (macOS만)**:
    ```bash
      $ brew install gitless
    ```
-   **Snapcraft를 통해 설치 (Linux만)**:
    ```bash
      $ snap install --channel=beta gitless
    ```
    그리고 `gl` 명령을 위한 별명을 설정합니다.
    ```bash
      $ sudo snap alias gitless-snap gl
    ```


### 사용법 {#사용법}

-   `gl` 명령을 사용하여 다양한 작업을 수행할 수 있습니다. 예를 들어, 도움말을 보려면:
    ```bash
      $ gl -h
      $ gl subcmd -h
    ```

=gitless=는 Git의 복잡성을 줄여주면서도 Git의 모든 기능을 활용할 수 있는 유용한 도구입니다. 詳細한 정보는 [Gitless 공식 문서][3]를 참조하세요.

@assistant 해당 오류는 여러 가지 이유로 발생할 수 있습니다. 여기 몇 가지 해결 방법을 제안합니다:


#### 1. 노드와 yarn 버전 확인 {#1-dot-노드와-yarn-버전-확인}

-   노드와 yarn의 버전이 최신인지 확인하세요. 일부 패키지는 최신 버전에서만 호환될 수 있습니다.
    ```bash
      $ node -v
      $ yarn -v
    ```


#### 2. 의존성 문제 해결 {#2-dot-의존성-문제-해결}

-   `gpu.js=와 =gl` 패키지가 사용하는 의존성들이 deprecated된 경우가 많습니다. 이러한 경우, 패키지의 최신 버전을 사용하거나, 대체 패키지를 찾는 것이 좋습니다.
    -   예를 들어, =rimraf=는 버전 4 이상을 사용해야 합니다.
    -   =glob=는 버전 9 이상을 사용해야 합니다.
    -   =inflight=는 사용하지 말고 =lru-cache=를 사용하세요.


#### 3. ES Module과 CommonJS 호환 문제 {#3-dot-es-module과-commonjs-호환-문제}

-   `ERR_REQUIRE_ESM` 오류는 ES Module과 CommonJS 간의 호환 문제로 발생합니다. 이 경우, 해당 모듈을 동적으로 임포트하거나, 호환되는 버전을 사용해야 합니다.

    -   예를 들어, `string-width` 모듈에서 =strip-ansi=를 임포트하는 부분을 수정해야 할 수 있습니다.

    <!--listend-->

    ```javascript
      // 동적으로 임포트하기
      const { default: stripAnsi } = await import('strip-ansi');
    ```


#### 4. prebuild-install과 node-gyp 문제 {#4-dot-prebuild-install과-node-gyp-문제}

-   =prebuild-install=이나 =node-gyp rebuild=가 실패하는 경우, 빌드 환경이 올바르지 않은 경우가 있습니다.

    -   필요한 빌드 도구들이 설치되어 있는지 확인하세요.

    <!--listend-->

    ```bash
      $ npm install -g node-gyp
      $ npm install -g prebuild-install
    ```


#### 5. 패키지 재설치 {#5-dot-패키지-재설치}

-   프로젝트의 `node_modules` 디렉토리를 삭제하고, `yarn.lock` 파일을 삭제한 후 다시 설치해 보세요.
    ```bash
      $ rm -rf node_modules
      $ rm yarn.lock
      $ yarn install
    ```


#### 6. 특정 패키지 버전 고정 {#6-dot-특정-패키지-버전-고정}

-   특정 패키지의 버전을 고정하여 호환성을 유지할 수 있습니다. 예를 들어, `package.json` 파일에서 다음과 같이 버전을 고정할 수 있습니다.
    ```json
      "dependencies": {
        "gpu.js": "^9.3.1",
        "gl": "^4.3.1",
        // 기타 의존성들
      }
    ```

이러한 방법들을 시도해 보시고, 여전히 문제가 발생한다면, 해당 패키지의 이슈 트래커나 공식 문서를 참조하여 더详细한 해결 방법을 찾으세요.
