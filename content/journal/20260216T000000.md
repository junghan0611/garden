### <span class="org-todo todo TODO">TODO</span> 06:06 단절: 파일 시스템 + Git = 노트 단위 무결성 보장이 없다 {#06-06-단절-파일-시스템-plus-git-노트-단위-무결성-보장이-없다}

```markdown
  Doltgres 이야기, 깊이 있는 질문입니다.

  문제의 본질

  지금 겪고 있는 것은 결국 이겁니다:

  파일 시스템 + Git = 노트 단위 무결성 보장이 없다

  - Git은 커밋 단위 스냅샷이지, 개별 파일의 생존을
  보장하지 않음
  - 에이전트가 파일을 0바이트로 만들어도 git add . 한
  방이면 역사에 묻힘
  - 1년마다 리포를 리셋하면 히스토리가 끊김 — 삶의 누적이
  아닌 단절

  Doltgres가 맞는 레이어인가?

  Dolt는 "Git for data" — 테이블 단위 diff, branch,
  merge를 제공합니다. 하지만:

  ┌──────────┬─────────────┬───────────────┬─────────────┐
  │          │     Git     │   Doltgres    │  필요한 것  │
  ├──────────┼─────────────┼───────────────┼─────────────┤
  │ 단위     │ 커밋 (전체  │ 행 (row-level │ 파일 (노트  │
  │          │ 스냅샷)     │  diff)        │ 1개)        │
  ├──────────┼─────────────┼───────────────┼─────────────┤
  │ 스키마   │ 없음        │ SQL 테이블    │ Denote      │
  │          │             │               │ 파일명 규칙 │
  ├──────────┼─────────────┼───────────────┼─────────────┤
  │ 히스토리 │ 리포 크기   │ 같은 문제     │ 영구 누적   │
  │          │ 폭발        │               │             │
  ├──────────┼─────────────┼───────────────┼─────────────┤
  │ 무결성   │ 수동 확인   │ 제약조건 가능 │ 자동 감지   │
  └──────────┴─────────────┴───────────────┴─────────────┘

  Dolt를 쓰면 INSERT INTO notes VALUES (...) + CONSTRAINT
  NOT NULL 같은 DB 수준 보호를 얻지만, Denote의 "파일명이
  곧 메타데이터"라는 우아함을 잃습니다. 오버킬이 될
  가능성이 높습니다.

  더 적절한 접근: Git 위에 노트 무결성 레이어

  Denote의 철학을 유지하면서 구조적 견고성을 얻으려면:

  1. 커밋 전 검증 (pre-commit hook)

  - 0바이트 파일 거부
  - 삭제된 노트 경고 (의도적 삭제인지 확인)
  - Denote 파일명 규칙 위반 감지
  - 필수 헤더 (#+title, #+filetags) 누락 검사


  2. 노트 레지스트리 (가벼운 메타 DB)

  bin/.note-registry  ← 모든 노트의 ID, 제목, 크기, 해시


  - 커밋마다 자동 갱신
  - diff하면 "어떤 노트가 사라졌는지, 크기가 급변했는지"
  즉시 파악
  - SQLite 하나로 충분, Dolt 불필요

  3. 히스토리 압축이 아닌 분리

  ~/org/          ← 현재 작업 리포 (가벼움)
  ~/org-archive/  ← 연도별 아카이브 (읽기 전용, git-lfs
  또는 bare)


  - 리포를 리셋하되 아카이브를 유지 → 히스토리 영구 보존
  - 노트 레지스트리가 아카이브와 현재를 이어주는 인덱스
  역할

  핵심

  1KB 텍스트로 존재를 복원하려면, 그 텍스트가 절대 조용히
  사라지지 않는 구조가 필요합니다.

  Dolt는 데이터셋/테이블용이고, 당신의 노트는 파일입니다.
  필요한 건 "DB 교체"가 아니라 Git 위에 노트 단위 안전망 —
   pre-commit 검증 + 레지스트리 + 아카이브 전략입니다.

  전체 내보내기 결과 나오면 이어서 진행합니다.
```
